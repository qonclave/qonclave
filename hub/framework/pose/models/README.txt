All pose model files live here. Everything in this folder is gitignored and
generated by setup - nothing here is committed and nothing is vendored in.

NPU (ARM64 / Snapdragon X), exported by setup:
  hrnet_pose.onnx      - HRNetPose w8a8 graph   (~0.9 MB)
  hrnet_pose.data      - weights                (~109 MB, referenced by the .onnx)
  metadata.json        - quantization scales/zero-points from the export
  hrnet_pose_ctx.onnx  - compiled HTP context binary (~29 MB), built on THIS host

Why nothing is committed:
  hrnet_pose.data is 109 MB. hrnet_pose_ctx.onnx is tied to the exact QAIRT
  build and HTP architecture that produced it, so a copy from another machine
  is at best useless and at worst subtly wrong.

The context binary is worth building:
  session init drops from ~6.0 s to ~0.30 s. If it is missing or stale,
  pose_pipeline falls back to the raw QDQ model - a slower start, not a
  failure. Regenerate it per host; never copy it between hosts.

How these get generated (automated):
  ..\setup\setup_pose.ps1 runs the whole flow on ARM64. hub\setup_hub.ps1
  calls it, and -SkipPose opts out.

Manual fallback, if you need the steps:
  1. Export from AI Hub (needs a free token from
     https://workbench.aihub.qualcomm.com -> Account -> Settings -> API Token):

       qai-hub configure --api_token YOUR_TOKEN
       qai-hub-models export hrnet_pose --target-runtime onnx --device "Snapdragon X Elite"

     The job output lands in job_<id>_optimized_onnx/ as model.onnx + model.data.

  2. Rename. The .onnx references its .data sidecar BY LITERAL FILENAME, so
     a plain file rename breaks the link and produces an opaque load error.
     Rewrite it instead:

       import onnx
       m = onnx.load("job_<id>_optimized_onnx/model.onnx")
       onnx.save_model(m, "hrnet_pose.onnx", save_as_external_data=True,
                       location="hrnet_pose.data", all_tensors_to_one_file=True)

     setup_pose.ps1 does exactly this, the same way setup_npu.ps1 does for
     CavaFace.

  3. Compile the context binary, ON THE TARGET HOST:

       import onnxruntime as ort
       c = ort.ModelCompiler(...)   # see setup_pose.ps1 for the full call
       # MUST pass graph_optimization_level=ort.GraphOptimizationLevel.ORT_ENABLE_ALL

     GOTCHA: ModelCompiler defaults to ORT_DISABLE_ALL, which fails with an
     NHWC layout-transform error along the lines of
       "Conv_token_61 ... com.ms.internal.nhwc ... not selected by that EP".
     That is not a broken export - it is the default optimization level.
     Takes ~4.6 s.

Verify the result:
  python hub\framework\pose\pose_pipeline.py benchmark <crop.jpg>
  Expect ~0.30 s session init and ~1.45 ms/inference, and "mode: npu".
  If it says "mode: cpu", the QNN EP did not bind - the session builder falls
  back silently by design, so this benchmark is how you find out.
